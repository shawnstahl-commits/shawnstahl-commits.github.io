SPÄTERE TECHNISCHE ANBINDUNG

Was die Händler-API an ScanQuest melden würde

Die echte Version würde eine Kaufbestätigung serverseitig validieren und jede Transaktion nur einmal belohnen. Personenbezogene Daten sollten dabei minimiert bzw. pseudonymisiert werden.

1) ScanQuest speichert serverseitig: { "customer_token": "pseudonymous-user-token", "partner_id": "market_123", "barcode": "4006381333931", "scanned_at": "SERVER_TIME" } 2) Kasse / Loyalty-System meldet später: POST /retail/purchase-confirmation { "partner_id": "market_123", "transaction_id": "receipt_987654", "customer_token": "pseudonymous-user-token", "barcode": "4006381333931", "purchased_at": "POS_TIME" } → gleicher Händler → gleicher Barcode → Scan muss VOR dem Kauf liegen → Zeitfenster der Kampagne muss eingehalten sein → Transaktions-ID darf noch nie verwendet worden sein → Belohnung wird exakt einmal gutgeschrieben
