SPÄTERE TECHNISCHE ANBINDUNG

Was die Händler-API an ScanQuest melden würde

Die echte Version würde eine Kaufbestätigung serverseitig validieren und jede Transaktion nur einmal belohnen. Personenbezogene Daten sollten dabei minimiert bzw. pseudonymisiert werden.

POST /retail/purchase-confirmation { "partner_id": "market_123", "transaction_id": "receipt_987654", "customer_token": "pseudonymous-user-token", "campaign_id": "family-weekend", "eligible": true, "purchased_at": "2026-09-30T18:00:00Z" } → ScanQuest prüft Partner + Kampagne + Transaktions-ID → Belohnung wird exakt einmal gutgeschrieben → Händler erhält nur Kampagnen-Kennzahlen
